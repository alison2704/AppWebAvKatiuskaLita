## Incidencias resueltas del despliegue
1. **Terminaciones de línea LF en `.bat`/`.ps1`**: el Write tool guarda con `\n`. `cmd.exe` puede fallar al parsear `.bat` con LF (sobre todo bloques `if (...)` multilínea y `goto`). **Solución:** convertir siempre con `sed -i 's/\r$//; s/$/\r/'`. Verificar con `tr -cd '\r' | wc -c` == `tr -cd '\n' | wc -c`.
2. **`$PSScriptRoot` vacío en el proceso elevado** (primer intento: buscó `C:\src` y creó el log en `C:\_tools\deploy.log`). **Solución:** no usar `$PSScriptRoot` en los valores por defecto de `param()`; resolver la carpeta del script con una cadena de alternativas (`$PSScriptRoot` → `$MyInvocation.MyCommand.Definition` → `.Path` → `Get-Location` → ruta absoluta literal) y **pasar `-Source` y `-LogFile` explícitamente desde el `.bat`**.
3. Dry-run sin privilegios validado: el script resuelve rutas y aborta correctamente en la comprobación de administrador con exit code 1.

## BUG CRÍTICO encontrado por las pruebas HTTP
- **VBScript no permite concatenar con `&` dentro de una `Const`** → error de compilación `800a0415 Expected literal constant`.
  - Estaba en `includes/config.asp`: `Const IMG_USER_DEF = DIR_USER & "/default.jpg"`.
  - Corregido con literales completos. **Regla: nunca usar `&`, operadores ni otras Const dentro de `Const` en VBScript.**
- Verificado que SQL Server es **2025 (17.0.5005.3) Express** → `OFFSET/FETCH` disponible.
- Las 4 consultas principales (canciones, álbumes, playlists, artistas con `FOR XML PATH`) se probaron directamente en SQL Server y funcionan.
- Añadido `GROUP BY` en la subconsulta `FOR XML PATH` de álbumes para no repetir artistas.
- Creado `_tools/checkasp.js`: verificador estático de bloques VBScript (If/For/Do/Select/Sub/Function/Class). Los 30 .asp pasan sin problemas.
